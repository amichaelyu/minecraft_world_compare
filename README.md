# minecraft_render

A browser viewer (three.js + bun) that shows two Minecraft Java worlds side by side with one
synced camera: the San Francisco replica (world A, the reference) and an SF world generated by
[arnis](https://github.com/louis-e/arnis) (world B).

World data is never committed. The worlds live outside the repo, and you point the viewer at them.

## 1. Get the two worlds

### A: the SF replica

Download it from **https://worldcraft.gg/sf** and extract it. By default the viewer looks for it
next to this repo, at `../San-Francisco` (the folder that holds `level.dat`). It is a Java 26.2 world,
about 6 GB.

### B: generate SF with arnis

```sh
git clone https://github.com/louis-e/arnis.git
cd arnis
cargo run --release --no-default-features -- \
  --output-dir="<where the world should go>" \
  --bbox="37.708,-122.515,37.812,-122.357"
```

Use exactly this bbox (`min_lat,min_lng,max_lat,max_lng`). The alignment transform in
`worlds.json` was fitted for it, so a different bbox would put world B in the wrong place. arnis
writes a world folder such as `Arnis World 1` (with `region/`, `level.dat` and `metadata.json`)
inside the output directory.

## 2. Point the repo at the worlds (data sources)

`worlds.json` (committed) lists the worlds: id, name, default path relative to the repo root, and
the transform that maps each world into world A's coordinates. Machine-specific paths go in
**`worlds.local.json`** (gitignored) in the repo root:

```json
{
  "sf":    { "path": "/path/to/San-Francisco" },
  "arnis": { "path": "/path/to/Arnis World 1" }
}
```

Or set environment variables `WORLD_SF_PATH` and `WORLD_ARNIS_PATH`. These override both files.
Region files are found under `dimensions/minecraft/overworld/region/` (26.x layout) or `region/`.

**Textures** come from your own Minecraft client jar (Java 26.2), which you get by launching 26.2
once from the official launcher. `build-assets` finds it in the launcher's standard folder, or
you can set `MINECRAFT_JAR=/path/to/26.2.jar`. Nothing extracted from the jar is committed.

## 3. Run it

```sh
bun install
bun run build-assets                    # texture atlas + block models -> cache/assets/
bun run src/server/lod.ts --prebuild    # far-distance LOD tiles for every world -> cache/lod/ (~1 min)
bun run dev                             # http://localhost:3000  (PORT to change)
```

Controls: click to fly (WASD, mouse, Space/Q, Shift fast). Tab switches to map mode, V to swipe
view, F3 toggles debug info, H shows help. The bottom-left panel has the landmark list and a
jump-to box.

## Alignment

`spike/` holds the throwaway Python (uv) scripts used to fit arnis → replica. The replica is
rotated **99.1°** against arnis at 1:1 scale; the details are in `spike/alignment-arnis.json`.
To refit after regenerating arnis with other settings, rerun the scripts in this order:
`extract2.py`, `peaks2.py`, then `refine.py`.
